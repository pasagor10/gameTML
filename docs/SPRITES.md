# ตรวจวงจรก้าวจริง — v0.4 (ล่าสุด)

## สิ่งที่ตรวจพบ
การอ่านช่องภาพเป็น 0→1→2→3→4→5→6→7→0 อยู่แล้ว ไม่มีการวนย้อน แต่ภาพ run-v2 หลายท่าขาอยู่ด้านหลังคล้ายกัน ขาดช่วงเหยียดเท้าไปด้านหน้า และมีตำแหน่งศีรษะ/ลำตัวเลื่อนในแต่ละช่อง การมีครบ 8 ช่องและ unit tests ผ่านจึงไม่ยืนยันคุณภาพท่าวิ่ง

## แก้แล้ว
- ทำ skeletal pose guide ใหม่ด้วยตำแหน่งสะโพก/เข่า/ข้อเท้าและครึ่งรอบของขาซ้าย–ขวา (tools/make-run-pose-guide.py)
- ใช้ guide + ภาพตัวละครเป็น reference ให้ built-in image_gen สร้าง run-v3-upper/lower ชาย–หญิงแทนชุดเดิม เก็บต้นฉบับเก่าทั้งหมด
- Register ใบหน้าหรือผมด้านหลังให้ตรงกันตลอดรอบ ลดการเลื่อนทั้งตัว ใช้ bob เล็กตามจังหวะ แต่ไม่บังคับให้ปลายรองเท้าอยู่ระดับเดียวกันทุกเฟรม
- ไม่เพิ่มความเร็วแอนิเมชันเพื่อกลบปัญหา RUN_STRIDE ยังเป็น 112 และเฟรมสัมพันธ์กับระยะจริง
- Sprite Lab ใช้ระยะเดินจำลอง 145 หน่วย/วินาทีเหมือนเกม เพิ่มช้า 1/2, 1/4, ถอยเฟรม, เลือกเฟรมตรง ๆ และแสดงทั้งรอบตามทิศให้เทียบได้
- ปุ่มตรวจเฟรมวาดภาพและอัปเดตหมายเลขทันที แก้อาการตัวเลขช้าหนึ่งเฟรมเมื่อแท็บเบื้องหลังถูกลดความถี่ requestAnimationFrame
- URL atlas มี revision ใหม่ เพื่อให้การเปิดรอบ/หน้าใหม่รับภาพฉบับล่าสุด

## หลักฐานและข้อจำกัด

# แก้จังหวะวิ่งและความชัด — v0.3

สถานะล่าสุด: ยืน 4 เฟรม + วิ่ง 8 เฟรม × 8 ทิศ × ชาย/หญิง รวม 192 เฟรม

## สาเหตุและการแก้
ก่อนหน้า importer ตัดภาพแต่ละเฟรมแล้วนำขอบรองเท้าไปติดพื้นเท่ากันทุกเฟรม จึงลบช่วงลอยตัว อีกทั้งใช้เวลา global ทำให้เดินเบากับวิ่งเร็วหมุนเฟรมเท่ากัน และบนมือถือกล้องลดภาพจนฮีโร่สูงประมาณ 68px

สร้าง run-v2 แยกเป็นสองแผ่นต่อเพศ (N–SE กับ S–NW) แผ่นละ 8 คอลัมน์ × 4 แถว เพื่อเน้นวงจรก้าวครบซ้ายและขวา เก็บต้นฉบับเดิมทั้งหมดไว้
Importer v2 ใช้ระดับพื้นร่วมต่อทิศ แต่เก็บตำแหน่งท่าระหว่างเฟรม จึงไม่ดึงเท้าลอยลงมาติดพื้น ขนาด run atlas ใหม่ 2048×2048 ต่อเพศ

จังหวะวิ่งผูกกับระยะเดินจริง: หนึ่งวงจรต่อระยะ 112 หน่วย จึงไม่รัวขาขณะเดินช้า/ดันขอบโลก
เพิ่มขนาดฮีโร่จาก scale .64 เป็น .78 และกำหนดกล้องมือถือขั้นต่ำ .82 ทำให้ความสูงที่อ่านได้ประมาณ 120px บนจอ 360–430px แทนประมาณ 68px เดิม (ขึ้นกับท่า)
ใช้ high-quality image smoothing และ snap ตำแหน่งวาดกับพิกเซลจริง; canvas เกมและ Sprite Lab รองรับ DPR สูงสุด 3 หน้า Lab ไม่ยืด canvas 256px ไปบนจอ Retina อีกต่อไป

## ตรวจแล้ว
`npm run check` และ tests 16 ข้อผ่าน รวมการคงช่วงลอยตัวครบทุกทิศ การเดินช้า/ดันขอบไม่หมุนขาเกินจริง การอ่านภาพบนมือถือ และระบบต่อสู้เดิม
ภาพและ animation ยังเป็นภาพที่เจน ต้องทดสอบความลื่นด้วยตาจริงและไม่ถือว่าตัวเลข tests ยืนยันคุณภาพเชิงศิลป์ทุกเฟรม
พรอมป์ต์ v2 เก็บใน assets/sprites/source/run-v2-prompts.json

# บันทึกชุดเดิม v0.2 (ประวัติ)

วันที่ 22 พฤศจิกายน 2026

## ส่งมอบและนำเข้าแล้ว
- ชาย: ยืน 4 เฟรม × 8 ทิศ และวิ่ง 6 เฟรม × 8 ทิศ
- หญิง: ยืน 4 เฟรม × 8 ทิศ และวิ่ง 6 เฟรม × 8 ทิศ
- รวม 160 เฟรม PNG โปร่งใสจริง; ภาพทุกเฟรมเป็นมือเปล่า
- เกมอ่าน atlas ตามทิศเดิน 8 ทิศจริง ไม่ใช้แค่พลิกภาพซ้ายขวา
- หยุดเดินแล้วคงทิศล่าสุด ส่วน Pause/เลือกการ์ดหยุดเวลาของภาพด้วย
- อาวุธอาชีพยังเป็นภาพที่วาดด้วยโค้ดอีกชั้น แยกจากตัวละคร; ฝึกหัดมือเปล่า
- Sprite Lab ดูทั้งสองตัว ทุกทิศ ยืน/วิ่ง เล่น/หยุด และทีละเฟรม

## ไฟล์

sources.json ระบุว่าจะใช้ฉบับแก้ โดยเก็บต้นฉบับเดิมไว้

- assets/sprites/heroes/male/run.png — 1536×2048

## มาตรฐานนำเข้า
ลำดับแถว: N, NE, E, SE, S, SW, W, NW
ช่อง 256×256; จุดยึดเท้า x128 y224; วิ่ง 10 FPS ยืน 4 FPS
Importer หาร่องโปร่งใสใกล้เส้นแบ่งแถวเพื่อหลีกเลี่ยงการตัดผม/รองเท้า แล้วจัดขนาดด้วย scale ร่วมต่อ sheet และยึดขอบล่างให้ตรงกัน
ไม่มีการวาดเติมภาพด้วย Python; ใช้เฉพาะตัดช่อง/จัด atlas/ตรวจ alpha ภาพแก้ขอบเจนใหม่ด้วย image_gen

จุดจับอาวุธอยู่ใน frames[direction-frame].hand มี handStatus=provisional เพราะยังไม่มี asset อาวุธจริงให้สอบเทียบ ใช้ใน renderer แล้ว ปรับเป็นรายเฟรมได้โดยไม่ต้องแก้ตัวละครต้นฉบับ

## ตรวจแล้ว
syntax check ผ่าน และ tests 13 ข้อผ่าน รวม 8 ทิศ การคงทิศเมื่อหยุด การวนเฟรม ขนาด atlas/ช่องและจุดยึดเท้าครบ 160 เฟรม กับระบบต่อสู้เดิม

เบราว์เซอร์ตรวจชายและหญิงใน Sprite Lab และเดินขึ้นในเกมเห็นด้านหลังตัวละครจริง

## ขอบเขตที่ต้องแยกให้ชัด
นี่คือชุดยืน/วิ่งที่จบและนำเข้าแล้ว ไม่ใช่ชุดภาพทุก action ของเกม
การโจมตีปัจจุบันใช้เอฟเฟกต์/อาวุธแยกชั้น การโดนตีใช้การกะพริบภาพ ยังไม่มี sheet ท่าโจมตีเฉพาะอาชีพ โดนตีและล้ม
รูปลักษณ์จากภาพที่เจนอาจมีรายละเอียดปลีกย่อยต่างระหว่างเฟรม ต้องประเมินอีกครั้งเมื่อมีอาวุธจริงและก่อนปล่อยงานภาพฉบับ production
ไม่เพิ่มหน้าบังคับเลือกเพศก่อนเล่น เลือกจริงยังเป็น Lv.10 ตามที่ตกลง
