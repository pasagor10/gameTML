# แผน TILMO ฉบับเริ่มต้น

วันที่: 22 พฤศจิกายน 2026 • ฉบับเสนอเพื่อคุยและปรับ • เอกสารแผนเดิม; สถานะที่ทำจริงดู IMPLEMENTATION.md

## 1. สิ่งที่ต้องพิสูจน์
ผู้เล่นรู้สึกว่า “รอบหน้าอยากลองอีก Build” มากกว่ารู้สึกว่าแค่รอพลังเพิ่ม
การเปลี่ยนภาพอย่างเดียวไม่รับประกันว่าคนจะกลับมา เรารู้เพียงว่าผู้ใช้ไม่พอใจการเล่นซ้ำของเกมเดิม ยังไม่มีข้อมูลยืนยันว่าสาเหตุเกิดจากส่วนใด

เสาหลักที่เสนอ:
1. เดินหลบแล้วมีผลจริง ศัตรูอ่านออกและความเสียหายหลบได้
2. เลือกอัปเกรดแล้วเห็นพฤติกรรมการโจมตีเปลี่ยนทันที
3. จบรอบแล้วได้ลองสิ่งใหม่ ไม่ต้องฟาร์มซ้ำเพื่อปลดล็อกความสนุกพื้นฐาน
4. ภาพน่ารัก เอฟเฟกต์สะใจ แต่ยังเห็นศัตรูและพื้นที่อันตราย

## 2. รูปแบบการเล่นที่เสนอ
- สนาม top-down เฉียง เดินอิสระ 8 ทิศทางตามภาพ 4–5 ผู้ใช้ยืนยันแล้วในวันที่ 22 พฤศจิกายน 2026
- ภาพ 1/3 ใช้เป็นอารมณ์หน้า Lobby ไม่ใช้การต่อสู้ด้านข้างเป็นรูปแบบสนามเดียวกัน
- เริ่มจาก 2D sprite ความละเอียดสูง + เงาสัมผัสพื้น + เรียงภาพตามตำแหน่งแนวตั้ง + ฉากหลายชั้น ให้รู้สึก 2.5D
- ไม่ใช้ภาพฉากเต็มจอแทนสนามที่เดินและชนได้จริง
- เริ่มทดสอบมือถือแนวตั้งและคอมแนวนอน โดยรักษาระยะมองเห็นภัยให้พอหลบได้ทั้งสองจอ ห้ามยืดภาพหรือให้จอกว้างยิงไกลกว่า
- ใช้ Phaser เป็นตัวเลือกแรกสำหรับการทดลองเท่านั้น ยังไม่สรุป engine จนผ่านการวัดบนมือถือเป้าหมาย
- หากผู้ใช้ต้องการโมเดล 3D หมุนกล้องได้จริง ต้องประเมิน pipeline และต้นทุนใหม่ก่อน

## 3. วงจรหลัก
กดเล่น → เดินหลบ/โจมตีอัตโนมัติ → เก็บ EXP → เลือก 1 ใน 3 → ประกอบ Build → Elite → บอส → ดูผล → ปลดล็อกทางเลือก → เล่นอีกครั้ง

การเลือกเป็นแกนความสนุก: เช่น ดาบวงกว้างช่วยเคลียร์ฝูง แต่ดาบพุ่งช่วยยิงเป้าหมายไกล แต่ละสายต้องมีจุดแข็งที่สังเกตได้
แพ้แล้วกลับเล่นใหม่ได้รวดเร็ว ไม่เสียพลังงานเข้าเล่น และไม่ขายการชุบชีวิตในต้นแบบ

## 4. ขอบเขต Combat Slice แรก
| ส่วน | ขอบเขตที่เสนอ |
|---|---|
| ฮีโร่ | นักดาบ 1 ตัว รูปลักษณ์เดียว ยังไม่มีหน้าสร้างตัวละคร |
| สนาม | ซากปรักหักพังป่า 1 สนาม มีสิ่งกีดขวางเล็กน้อย |
| รอบ | 5 นาที บอสเริ่มประมาณนาที 4 และชนะ/แพ้ภายในนาที 5 |
| โจมตี | โจมตีพื้นฐานอัตโนมัติ + เคลื่อนที่เอง |
| สกิลระหว่างรอบ | 4 สกิลเชิงรุก + 2 passive แต่ละตัวอัปได้ 3 ระดับ |
| ช่อง Build | เชิงรุก 2 ช่อง ไม่นับดาบหลัก + passive 2 ช่อง |
| Evolution | 2 สูตรที่มีวิธีเล่นต่างกัน ไม่ใช่แค่เพิ่มตัวเลข |
| ศัตรู | Slime ไล่ตาม, Runner เร็วเปราะ, Archer ยิงแบบเตือน |
| Elite | Slime ขนาดใหญ่พร้อมวงเตือน ไม่ต้องสร้างตัวละครชนิดใหม่ |
| บอส | 1 ตัว เริ่มจากพุ่งตรงกับทุบวงเตือน 2 ท่า |
| หน้าจอ | เริ่มเล่น / ต่อสู้ / เลือกอัปเกรด / ผลรอบ |
| เซฟ | ตั้งค่าและปลดล็อกในเครื่องสำหรับทดลอง แจ้งว่าเซฟอยู่เฉพาะเครื่อง |
| เสียง | เสียงโจมตี โดน เก็บ EXP อัปเกรด บอส และปิดเสียงได้ |

สกิลเสนอ: Flame Orbit, Frost Shard, Spark Chain, Gust Pulse; passive: เพิ่มระยะ/พื้นที่, ลดคูลดาวน์
Evolution เสนอ: Flame Orbit Lv.3 + พื้นที่ Lv.2 → Inferno Ring; Frost Shard Lv.3 + คูลดาวน์ Lv.2 → Blizzard Volley
ชื่อและสูตรเป็นแบบทดลอง ต้องปรับจากความแตกต่างในการเล่นจริง

ระบบสุ่ม: ไม่เสนอของเต็มระดับ ห้ามการ์ดซ้ำในชุดเดียวกัน ให้สกิลใหม่ก่อนช่องเต็ม หลังช่องเต็มให้อัปเฉพาะที่ถือ แสดงสูตร Evolution ที่ค้นพบ และมี fallback ที่ใช้ได้เมื่อไม่มีตัวเลือกอัปเกรด

## 5. จังหวะรอบแรก
| เวลา | ประสบการณ์เป้าหมาย |
|---|---|
| 0–10 วินาที | พร้อมเล่นทันทีหลังโหลด สอนการเดินด้วยข้อความสั้น |
| 10–30 วินาที | เลเวลแรก เลือกสกิลและเห็นผลทันที |
| 30–90 วินาที | เลือกทิศทาง Build และเริ่มเจอ Runner |
| 90–180 วินาที | Archer บังคับเปลี่ยนตำแหน่ง และ Elite แจกหีบ |
| 180–240 วินาที | เปิดโอกาสได้ Evolution และมีฝูงทดสอบ Build |
| 240–300 วินาที | หยุดเกิดฝูงไม่จำเป็น บอสมีท่าที่อ่านออกและหลบได้ |
| จบรอบ | เห็นสาเหตุแพ้/สรุป Build/สิ่งที่ปลดล็อก พร้อมปุ่มเล่นอีก |

ทั้งรอบหยุดเมื่อเลือกการ์ดหรือ Pause เวลาที่ใช้วัดรอบไม่นับช่วงหยุด บอสไม่เกิดทับตัวผู้เล่น ท่าเตือนต้องต่างจากสีเอฟเฟกต์ผู้เล่น หากหมดเวลาและบอสยังไม่ตายให้จบรอบแบบไม่ผ่านพร้อมอธิบาย ไม่ต่อรอบไปเรื่อย ๆ

## 6. ภาพและ UI
- ยึดสีฟ้าเขียวของฉาก ทองสำหรับรางวัล แดง/ม่วงที่อ่านชัดสำหรับภัย ไม่พึ่งสีอย่างเดียว
- Chibi Cartoon HD ตัวละครขอบชัด เงาติดพื้น ฉากมีความลึกตามภาพ 4–5
- HUD ต่อสู้เหลือ HP, เวลา, เป้าหมาย, EXP, Pause และข้อมูล Build ที่จำเป็น
- ไม่มีร้านค้า แชต กิลด์ กระเป๋าใหญ่ หรือจุดแดงเต็มหน้าระหว่างต่อสู้
- สกิลใน Slice ทำงานอัตโนมัติ ไม่เริ่มด้วยปุ่มกดสกิล 4–5 ปุ่ม เพิ่มปุ่มพิเศษภายหลังเมื่อมีเหตุผลด้านการเล่น
- มือถือ joystick; คอม WASD/ลูกศร; เลือกการ์ดด้วยแตะ/คลิก/1–3; Pause ด้วยปุ่มหรือ Esc
- ภาพ 2 เป็นแนวทางตัวละครและวัสดุ ไม่ได้อนุมัติ 6 อาชีพ/หลายเพศ/หลายรูปลักษณ์ในต้นแบบ
- ภาพ 6 เป็นแนวทางแบรนด์ ต้องออกแบบไอคอนขนาดเล็กแยกก่อนใช้งานจริง
- ผลิต asset แยกฮีโร่ มอนสเตอร์ พื้นฉาก วัตถุ เอฟเฟกต์ และ UI; ทดสอบ animation กับมุมกล้องก่อนผลิตทั้งชุด

## 7. Idle และความก้าวหน้า: ทำหลัง Combat ผ่าน
Adventure: เล่นเองเพื่อผ่านด่านใหม่และปลดล็อก Build
Idle Camp: รับวัตถุดิบทั่วไปขณะออฟไลน์ ไม่ผ่านบอสแทนผู้เล่น
Auto: ข้อเสนอให้ใช้ได้เฉพาะด่านที่ผ่านแล้ว ไม่อยู่ใน Slice แรก

เริ่ม progression ด้วยการปลดล็อกตัวเลือก มากกว่าบวกพลังถาวรจำนวนมาก จบรอบแรกให้รางวัลแน่นอนหนึ่งอย่าง ต้องบอกชัดว่าอะไรอยู่ถาวรและอะไรรีเซ็ต
Idle จำกัด 8 ชั่วโมงเป็นสมมติฐานจากเอกสารแนบ ยังต้องทดสอบอัตรารางวัลและเหตุผลในการกลับมา
เมื่อมี backend ให้เซิร์ฟเวอร์ถือเวลา/สิทธิ์รับรางวัล/ยอดคงเหลือ และรับรางวัลซ้ำไม่ได้ ห้ามนำเซฟ local ทดลองมาเชื่อถือเป็นเงินจริง

## 8. ลำดับงานและจุดตัดสินใจ
1. ล็อกรูปแบบสนามและมือถือทดสอบ → อนุมัติขอบเขต Slice
2. ทดลองภาพเคลื่อนไหว 1 ฮีโร่ + Slime + ฉากย่อย พร้อมทดสอบการอ่านภาพและ FPS; ใช้งานภาพทิศทางจริงตั้งแต่แรก ไม่เลื่อนปัญหาภาพไปท้ายงาน
3. สร้าง Combat Slice ให้จบรอบได้ พร้อม event วัดผลและเซฟทดลอง
4. ทดสอบ 5 คนรอบแรก แก้การควบคุม/อ่านภัย/เข้าใจการ์ด ก่อนขยายเป็น 20–30 คน
5. ผ่านเกณฑ์ความสนุก → เพิ่ม Lobby เล็ก เซฟ backend และ Idle Camp
6. เมื่อมีคนกลับมา → เพิ่มเนื้อหาและทดสอบ D1/D7
7. ค่อยพิจารณา Founder Pack 35 บาทแบบ cosmetic ตามแนวคิดเดิม ราคาและระบบชำระเงินยังไม่ใช่ข้อสรุป

ไม่กำหนดวันเสร็จก่อนรู้ทีม pipeline งานภาพ และเครื่องทดสอบ แต่ละขั้นต้องมีสิ่งที่เล่น/ตรวจได้และเงื่อนไขผ่าน ไม่วัดด้วยจำนวนฟีเจอร์อย่างเดียว

## 9. สิ่งที่ยังไม่ทำ

สิ่งเหล่านี้ใน GDD และภาพเป็นแนวคิดระยะถัดไป ไม่ใช่ backlog ที่อนุมัติทั้งหมด

## 10. เรื่องที่ต้องตกลงก่อนเริ่มเขียนเกม
- สนามเดินอิสระหรือด้านข้าง? ข้อเสนอ: เดินอิสระตามภาพ 4–5
- 2D ให้ดูมีมิติหรือโมเดล 3D จริง? ข้อเสนอ: 2D ให้ดูมีมิติสำหรับ Slice
- มือถือจริงที่จะใช้ทดสอบรุ่นใด? ข้อเสนอเบื้องต้น: Android RAM 4 GB, เป้าหมาย 30 FPS คงที่ และ 60 FPS บนเครื่องที่รองรับ; ยังไม่ได้วัด
- Guest ก่อนบัญชี? ข้อเสนอ: เข้าเล่นได้ทันที แล้วค่อยมีบัญชีเมื่อมีระบบเซฟออนไลน์
- คงบัญชีเดิมร่วมกันไหม? ข้อเสนอ: แยกเซฟและเศรษฐกิจ ใช้ระบบเดิมเป็นตัวอย่างได้แต่ต้องตรวจเป็นรายส่วน

ทั้งหมดในหมวดข้อเสนอเปลี่ยนได้ระหว่างคุย ยังไม่ใช่การยืนยันจากผู้ใช้
